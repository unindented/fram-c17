# Architecture

`fram` is a small C17 static photo and video gallery generator. It reads project configuration, a directory tree of media, and Mustache templates. It writes the generated files to a gallery-owned directory. This document describes the code structure. See [README.md](README.md) for usage and template behavior.

## Layout

- [src/app/](src/app/): Process entry point, command-line interface, and command boundaries.
- [src/build/](src/build/): Build orchestration, parallel phases, templates, manifest population, and output writing.
- [src/domain/](src/domain/): Gallery configuration, albums, media items, and the output manifest.
- [src/formats/](src/formats/): Boundaries for HTML, JPEG, EXIF, and TOML data.
- [src/runtime/](src/runtime/): Filesystem, process, video, and thread-pool services that interact with the host.
- [src/core/](src/core/): Small reusable primitives, containers, diagnostics, text, and path logic.
- [tests/](tests/): Golden test suite and the shared unit-test support library ([tests/test_support.h](tests/test_support.h)).
- [CMakeLists.txt](CMakeLists.txt) and [CMakePresets.json](CMakePresets.json): Project entry point and supported build configurations.
- [cmake/](cmake/): Build profiles, quality tools, packaging, the golden test driver, and reusable cross toolchains. [BUILD.md](BUILD.md) documents their boundaries and policy.
- [vendor/](vendor/): Bundled dependencies (`sharedstuff`, `copt`, `tomlc17`, `stb`, `mustache4c`, `acutest`).

First-party dependencies point inward:

- `app` can depend on all inner directories.
- `build` can depend on `domain`, `formats`, `runtime`, and `core`.
- `domain` can depend on `formats`, `runtime`, and `core`.
- `formats` and `runtime` can depend on `core`.
- `core` cannot depend on another first-party directory.

A module can skip layers. Modules in the same directory can depend on each other. First-party include directives start at the `src/` root. For example, a module includes `"core/error.h"`. This convention makes each dependency visible at the call site. Vendored support is outside the first-party hierarchy.

## Entry point and commands

`main` ([src/app/main.c](src/app/main.c)) only calls `cli_dispatch` ([src/app/cli_dispatch.h](src/app/cli_dispatch.h)). This separation lets unit tests link the code that maps an action to an exit code. `cli_dispatch` uses `cli_parse` ([src/app/cli.h](src/app/cli.h)) to parse the command line. `cli_parse` selects a subcommand and one of four actions: version, help, run, or error. For the run action, `cli_dispatch` calls one of these functions:

- `cmd_build_run` ([src/app/cmd_build.h](src/app/cmd_build.h)): generates the gallery.
- `cmd_config_run` ([src/app/cmd_config.h](src/app/cmd_config.h)): loads `fram.toml` and prints the resolved config.

`cli.c` is the one translation unit that defines `COPT_IMPL`. `cli_parse` never prints or exits. Every command returns `enum ExitCode` ([src/app/exit_code.h](src/app/exit_code.h)): `EXIT_CODE_OK` (0), `EXIT_CODE_FAILURE` (1), or `EXIT_CODE_USAGE` (2).

## Build pipeline

The build has two layers:

- `cmd_build_run` is the outer boundary. It calls `cmd_build_execute`. On failure, it prints the collected diagnostic to `stderr` exactly once.
- `cmd_build_execute` owns the `BuildState`, calls eight phases in sequence, and writes the verbose log. [album_scanner](src/build/album_scanner.h) builds the album tree and probes media. [manifest_builder](src/build/manifest_builder.h) plans output paths. [derivative_renderer](src/build/derivative_renderer.h) generates media output. [page_renderer](src/build/page_renderer.h) renders album pages. [site_writer](src/build/site_writer.h) writes the generated gallery.

No phase writes a failure diagnostic directly to `stderr`. Each phase returns errors to its caller. Most phases return one message through a fixed `(char* err, size_t err_len)` pair. The boundary copies this message to the diagnostic buffer. A parallel phase can report many failures. It appends up to twenty distinct failures and a count of the remainder to a growable `StringBuffer`.

Verbose status is separate from diagnostics. The main thread writes phase status lines. Workers use `flockfile` and `funlockfile` to write a synchronized `\r<label> n/total` progress line that counts completed jobs, such as `probing media 3/12`.

The phase order follows the data dependencies. A template can read media dimensions, album covers, and descendant counts. These values are not complete until the tool builds the album tree and probes every media item. The build therefore constructs all arena-owned strings serially, then uses separate parallel phases to probe media, generate derivatives, and render pages.

1. **Load inputs** (`load_build_inputs`): The tool uses `gallery_config_load` to read and validate `fram.toml`. It requires each configured read root to be a usable directory, reporting the cause when one is not, and skipping the optional asset root when a gallery ships none. `manifest_builder_check_output_dir` then rejects an `output_dir` at or below `input_dir`, `templates_dir`, or `assets_dir`, before any input tree is walked. Then `fs_list_files_with_suffixes(paths, input_dir, output_dir, suffixes, ...)` finds and sorts JPEG, MP4, and asset sources. Every walk of an input tree leaves `output_dir` out by identity, so a symlink into the output tree cannot feed an earlier build's outputs back in as inputs. When an MP4 exists, the phase verifies `ffmpeg` and `ffprobe` once.
2. **Build album skeleton** (`build_album_skeleton` -> `album_scanner_build_skeleton`): The tool walks the sorted media paths serially. It creates the root and nested albums, allocates every arena-owned string and media record, slugifies generated album and media output names, plans page and media paths, and builds the flat media array. It then fills parent, child, cover, and count relationships. Raw directory basenames become album titles with `_` displayed as a space. The phase also allocates one video-frame slot per media item and one rendered-page slot per album.
3. **Probe media** (`probe_media` -> `album_scanner_probe_media`): `job_run` dispatches one job for each media item. An image job reads the source, probes its JPEG dimensions, reads its EXIF orientation, and calculates its presented and derivative dimensions. A video job probes duration, chooses the configured frame time or the midpoint when that time is beyond the end, extracts one auto-rotated temporary JPEG, and probes that frame's dimensions. Each job writes only scalar fields in its media record and its own temporary-frame and error slots. After all workers finish, `pool_run` joins them. Then `job_run` adds each distinct message to the growable error buffer, one line each, up to twenty, followed by a count of the remaining failures. The optional progress line is the only worker output to `stderr`.
4. **Manifest** (`populate_output_manifest` -> `manifest_builder_populate`): The tool records all output paths for album pages, derivatives, originals, aggregates, and assets. It does this before it writes a generated file. It rejects four types of conflict:
   1. Two producers can claim the same path. `manifest_add` rejects the second claim. Paths that differ only in ASCII case are the same path, because a case-insensitive filesystem such as the macOS default stores them as one file. The comparison folds only `A-Z` to `a-z`. Other bytes must match exactly.
   2. One output can use `a/b` while another uses `a/b/c`. The first path must be a file, but the second path requires a directory at `a/b`. `manifest_find_prefix_collision` detects this conflict after the tool records all paths. It folds ASCII case in the same way, so `A/B` and `a/b/c` also conflict.
   3. An output can name an existing build input. `manifest_builder_populate` compares the device and inode of each file. It checks the config, all discovered media and assets, and every file below `templates_dir`. The template tree includes partials and templates that no configuration names. A missing `templates_dir` adds no inputs, although load inputs has already rejected one in a full build. A `templates_dir` that exists but cannot be walked fails the build.
   4. An output can land at or below `input_dir`, `templates_dir`, or `assets_dir`, even where no file exists yet. The next build would discover a new file below `input_dir` as media and would copy a new file below `assets_dir` as an asset. The same build could read a new file below `templates_dir` as a partial. `manifest_builder_check_output_dir` has already compared the device and inode of each root with the nearest existing ancestor of `output_dir` and each of that directory's ancestors, during load inputs. That rejects an `output_dir` inside a root before any walk, whether or not `output_dir` exists yet. `manifest_builder_populate` runs the same check again as a backstop, so no caller can skip it, and then compares each root with each existing directory between `output_dir` and the output. That catches a symlink inside `output_dir` that leads into a root. These comparisons detect alternate spellings and symlinked roots. A sibling directory such as `photosx` does not match. A missing root is skipped. The tool runs this check before the input-file check, so an output below a root reports this conflict.
5. **Prepare output** (`prepare_output_dir`): The tool creates `output_dir` with `fs_mkdir_p`. This is the build's first write, so a build that an earlier phase refuses creates nothing, not even an empty `output_dir`. Later writes create their own parent directories.
6. **Generate derivatives** (`generate_derivatives` -> `derivative_renderer_generate`): A second `job_run` phase owns one media item per job. It skips each non-empty derivative at least as new as its source and skips an original only when its size also matches. For stale image output, the job decodes and applies EXIF orientation, in place for an upright source. For stale video output, it decodes the retained auto-rotated frame. Every decode uses one size hint, the largest configured derivative, computed once per build. Before decoding, each job reserves its source's pixel count from one process-wide decode budget and holds the reservation until it releases the decoded image, so the number of concurrent full-size decodes is bounded by the budget rather than by the worker count. It loops over the ordered derivative definitions, applies each definition's center-crop policy and bounding box, encodes the result as JPEG, and copies the original source. Each video job unlinks its temporary frame when it finishes.
7. **Render pages** (`render_album_pages` -> `page_renderer_render_pages`): A third `job_run` phase renders each album through the configured album template into its result slot. Each render reads the complete immutable album set and uses the current album's `path_to_root` to turn output-root-relative URLs into page-relative URLs.
8. **Write** (`write_generated_site` -> `site_writer`): The tool writes the album pages first. Then it renders and writes each aggregate template and copies the discovered assets below `assets/`. Writes truncate their destination in place, so this phase is not transactional at any level: it does not remove outputs that are absent from the current manifest, a late template failure can leave new, old, and stale files together, and an interrupted write can leave one output truncated. The recovery for all three is to delete the output directory and build again.

## Modules

### Domain (`src/domain`)

- [gallery_config](src/domain/gallery_config.h): Defines `GalleryConfig`, `GalleryDerivative`, and the config load and print operations. An arena owns the copied values that the load operation validates and normalizes. The load operation rejects a key outside the schema, at the top level or in a derivative table, and applies optional defaults. Later phases use the resolved config without changing it. `base_url` needs an `http://` or `https://` scheme and a non-empty host. The scheme comparison is case-insensitive. The module removes trailing `/` characters from `base_url` and each configured directory. It also validates template names and the ordered named derivative table and builds the derivative recipe.
- [album](src/domain/album.h): Defines `Album`, one generated page and its immediate contents. A per-album arena owns its strings, media records, and pointer arrays. The album records its raw source directory, generated slug path, parent, immediate children and media, recursive cover and item count, output path, encoded URL, depth, and relative path to the output root.
- [media_item](src/domain/media_item.h): Defines `MediaItem`, one JPEG or MP4 source, and `MediaDerivative`, one configured output for that item. The serial skeleton pass fills source, derivative-array, original, and encoded URL fields. The probe phase fills only scalar duration, orientation, and dimension fields. The media derivative array stays aligned with `GalleryConfig.derivatives`. `media_item_encode_url` percent-encodes each path while preserving `/` separators. `media_item_has_extension` and `media_item_is_video_path` are the one ASCII-case-folding extension test that the skeleton pass and the video-tool check both use to classify a source.
- [manifest](src/domain/manifest.h): An insertion-ordered map from `output_path` to `source_label`. The tool creates it before it renders page templates or writes output files. A hash index keyed by the ASCII-folded path lets `manifest_add` reject a duplicate in O(1) average time. Two paths that differ only in ASCII case are duplicates. Other bytes, including non-ASCII bytes, compare exactly. `manifest_find_prefix_collision` finds a path that is a `/`-delimited prefix of another path. For example, it finds the conflict between `a/b` and `a/b/c`, and between `A/b` and `a/b/c`.

### Build (`src/build`)

- [template](src/build/template.h): `template_render_file` uses mustache4c to render a template with a `TemplateContext`. Template names must be safe relative paths, and partial names use a restricted identifier grammar. Each render has three limits. The partial-expansion limit stops a partial that includes itself, so every render terminates. The output-byte limit bounds the output buffer. The distinct-partial limit bounds the compiled-partial cache. The limits do not bound the total memory of a render. Templates are trusted input, and a template's nested sections use memory in proportion to the iterations that they request. All interpolation is HTML-escaped; unescaped Mustache interpolation is rejected. A media node resolves configured derivative names dynamically, so a new `xl` definition becomes `xl.url`, `xl.width`, and `xl.height` without a C model change.
- [album_scanner](src/build/album_scanner.h): Owns the serial skeleton pass and the first parallel phase. `album_scanner_build_skeleton` creates albums and media from sorted source paths, plans their output, and completes their relationships. `album_scanner_probe_media` fills only the scalar fields below the probe boundary and retains one temporary JPEG path per video.
- [job](src/build/job.h): Defines `job_run` and `job_set_error`. `job_run` owns one phase's error slots, one per job, and connects the three parallel phases to the worker pool. It reports synchronized progress and collects at most twenty distinct diagnostics plus a count of the remainder. Each job latches its first diagnostic into its own slot through `job_set_error` and writes its results into its own caller-owned slot.
- [output_path](src/build/output_path.h): Reports a generated output path that exceeds either output-path limit, with one wording for every producer, and builds the `../` prefix from an output file back to the output root. `album_scanner`, `manifest_builder`, and `site_writer` share it.
- [manifest_builder](src/build/manifest_builder.h): Builds the [manifest](src/domain/manifest.h) before the tool writes a generated file. `manifest_builder_populate` records every album page, derivative, original, aggregate, and asset output. It rejects duplicate paths, nested paths below an output file, outputs at or below `input_dir`, `templates_dir`, or `assets_dir`, and outputs that overwrite build inputs. `manifest_builder_check_output_dir` rejects an `output_dir` at or below any of the three roots before the build walks an input tree, whether or not `output_dir` exists yet. `manifest_builder_populate` runs it again as a backstop, then checks the directories below `output_dir`. The duplicate and nesting checks fold ASCII case. Build inputs include the config, sources, assets, and every file below `templates_dir`, which includes partials. The root and input checks compare device and inode values. They detect alternate spellings, hard links, symlinks, and case-insensitive paths to the same file or directory. `manifest_builder_derive_template_output` and `manifest_builder_derive_asset_output` derive each aggregate and asset output path for both the manifest and `site_writer`, so the path the manifest checked is the path that is written.
- [derivative_renderer](src/build/derivative_renderer.h): The second parallel phase. `derivative_renderer_generate` checks each named derivative's freshness, decodes and orients source images or retained video frames once, applies data-driven crop and fit rules, writes every stale derivative, and copies originals. Derivative paths contain the output-affecting recipe and append the derivative name to a full-filename slug that includes the source extension, while originals use a stable namespace.
- [page_renderer](src/build/page_renderer.h): The third parallel phase. `page_renderer_render_pages` renders each album into a per-index result slot. Each render reads the complete album set through a deeply `const` template context.
- [site_writer](src/build/site_writer.h): Writes the generated gallery from the rendered results. It writes each album page first. Then it renders and writes aggregate templates and copies enumerated assets.

### Formats (`src/formats`)

- [image](src/formats/image.h): Buffer-to-buffer JPEG probing, RGB decoding, EXIF-orientation transforms, linear-light resizing, zero-copy crop views, bounded JPEG encoding, and aspect-ratio calculations. The module wraps stb and performs no filesystem I/O.
- [exif](src/formats/exif.h): Reads the IFD0 orientation from JPEG EXIF data. Missing or malformed metadata falls back to top-left orientation.
- [html](src/formats/html.h): HTML escaping of untrusted text for generated markup.
- [toml](src/formats/toml.h): TOML text validation at the boundary where parsed bytes become owned text. `toml_require_known_keys` is the shared unknown-key check: it rejects the first table key that a loader's list of known keys does not contain.

### Runtime (`src/runtime`)

- [pool](src/runtime/pool.h): Runs indexed jobs through a bounded pthread pool. It completes all jobs, even if one job fails. It joins all workers before it returns. It also gets the default worker count from the number of online CPUs.
- [fs](src/runtime/fs.h): Finds and sorts matching regular files in a directory tree. It reads arbitrary byte files and rejects files that change size during a read. It also creates directories, writes files, copies files, reports whether a path exists, requires a path to be a usable directory and reports the cause when it is not, and gets timestamps and device and inode values. Writes overwrite their destination in place and are neither atomic nor synced: a reproducible output directory makes deleting it and rebuilding a cheaper recovery than a temporary-file protocol. A new file gets mode `0666` reduced by the process umask. The directory walk follows symlinked directories but walks each directory once, by device and inode. A cycle or a second alias of a directory is skipped, so an aliased directory publishes one copy of its media. A caller can also name one directory to leave out, which the walk records as already visited, so every path to it is skipped. The build leaves out `output_dir`. The walk visits entries in byte order and each symlinked directory only after every real one, so the listed path is the one without a symlink when one exists. It closes each directory before it descends, so only one directory is open at a time. It also skips dangling links and entries removed during the scan. `fs_read_file` takes a size limit from each caller and checks it against the `fstat` size of the opened file before any read or allocation.
- [proc](src/runtime/proc.h): Runs one argument vector without a shell and captures bounded process output. It drains standard output and standard error together so neither pipe can block the child. A failed exit's reason ends with the newest standard-error bytes that fit, because the child's last line usually names the cause.
- [video](src/runtime/video.h): Wraps `ffprobe` duration probing and `ffmpeg` auto-rotated JPEG extraction. Extracted frames use secure temporary files that the caller owns.

### Core (`src/core`)

- [ascii](src/core/ascii.h): Locale-independent ASCII byte classification.
- [error](src/core/error.h): Uniform diagnostic reporting for fallible actions.
- [fram_version](src/core/fram_version.h): The tool name and version fixed when the build tree was configured.
- [grow](src/core/grow.h): Doubling-capacity arithmetic shared by the growable containers.
- [parse](src/core/parse.h): Parsing of terminated text into scalar values.
- [path](src/core/path.h): Path construction and validation. `path_relative_below` returns the part of a path below a root by textual comparison. `manifest_builder` plans each asset output from it, and `site_writer` copies the asset to the path `manifest_builder_derive_asset_output` derives from it, so the two cannot disagree.
- [path_list](src/core/path_list.h): Growable list of path strings.
- [text](src/core/text.h): Text copying, normalization, and validation.

## Cross-cutting conventions

- **Ownership**: Arenas own groups of allocations. `GalleryConfig` owns one arena, and each album owns another. Some functions return a separate buffer. These functions include `template_render_file`, `string_buffer_steal`, `fs_read_file`, image operations, and video frame extraction. They transfer buffer or path ownership to the caller. The caller must use the matching release operation.
- **Text representation**: An owned string is a `NUL`-free C string. Only a borrowed slice or byte buffer carries a separate length. Examples include callback data from mustache4c and JPEG data returned by `fs_read_file`. This representation makes `strlen` accurate for owned strings while preserving arbitrary media bytes.
- **Text input checks**: `fs_read_file` accepts arbitrary bytes. Text consumers such as the TOML and template readers explicitly reject an embedded `NUL`. `toml_datum_is_text` also rejects a TOML string that contains a decoded `NUL`. These checks prevent silent truncation of generated output without imposing a text policy on media I/O.
- **Return values**: A producer returns a pointer or `NULL`. An action returns `0` or `-1`. A predicate returns `bool`.
- **Diagnostic buffers**: A fallible action can take a final `(char* err, size_t err_len)` pair. `error_report` fills this buffer and marks truncated text with `...`. Filesystem, image, process, and video actions use a `(char* reason, size_t reason_len)` pair instead. This pair contains a reason fragment. The caller adds the operation and file information.
- **Diagnostic text**: First-party diagnostics use lowercase prose and name the failed operation first. They use single quotes for literal names and values. External messages keep their original capitalization and punctuation. An unbounded value follows the cause, so truncation removes the value instead of the reason.
- **Path safety**: Template names must be safe relative paths. Partial names use a more restrictive identifier grammar. Media source paths retain filesystem bytes, while generated album segments and media filenames are lowercase ASCII slugs. Output-root-relative URLs pass through the URL encoder, and templates prefix them with the current page's `path_to_root`. Configured output names are checked before the tool joins them to `output_dir`. These text checks prevent `.` and `..` traversal. Input-root identity checks, the walks' exclusion of `output_dir`, and input-identity checks cover existing symlink aliases at their separate boundaries.
- **Input size limits**: Each `fs_read_file` caller passes a limit for the kind of file it reads. The read checks the limit before it allocates, so an oversize file is never loaded. `album_scanner` and `derivative_renderer` read media with `IMAGE_INPUT_LEN_MAX` from `image`, the decoder's `INT_MAX` input limit, which a larger image could not pass anyway. `CONFIG_FILE_LEN_MAX` in `gallery_config` is 1 MiB. `TEMPLATE_FILE_LEN_MAX` in `template` is 4 MiB for each template and partial. `fs_copy_file` streams an original, so it has no size limit.
- **Path limits**: The tool checks each generated output path against two limits. `OUTPUT_PATH_RELATIVE_LEN_MAX` limits the complete relative path. `FILENAME_LEN_MAX` limits each path segment. `output_path_check_limits` reports either failure the same way for every producer.
- **Parallel ownership**: The serial skeleton pass performs every allocation into album arenas. A worker receives immutable shared context and owns one index in each mutable result array. `pool_run` joins all workers before the main thread reads those slots.
